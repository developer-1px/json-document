# 왜 json-document인가

문서 앱에서 제목을 바꾸고, 표에서 셀을 고치고, 보드에서 카드를 옮기는
모습은 서로 다릅니다. 데이터 아래에서는 모두 같은 일이 일어납니다. 현재
값을 읽고, 변경할 위치를 찾고, 변경이 유효한지 확인한 뒤 새 값을 적용합니다.

제품마다 이 과정을 따로 구현하면 변경을 기록하는 방식도 함께 갈라집니다.
저장과 실행 취소, 다른 화면의 구독, 협업 로그가 각 제품의 이벤트와 상태
구조에 묶입니다. 편집 화면을 하나 더 만들 때마다 같은 기반 작업을 다시
만들게 됩니다.

json-document는 이 공통 과정을 `JSONDocument`라는 작은 API로 제공합니다.
화면은 각 제품이 원하는 방식으로 그리되, JSON을 읽고 변경하는 계약은 함께
사용할 수 있습니다.

## 하나의 변경 형식

표의 셀과 문서의 블록은 생김새가 다르지만 JSON 안에서는 모두 주소를
가집니다. json-document는 한 위치를 JSON Pointer로 가리키고, 여러 위치를
JSONPath로 찾습니다. 값을 바꿀 때는 JSON Patch를 사용합니다.

이 형식을 공유하면 화면에서 시작한 변경을 저장소나 다른 탭에서도 같은
뜻으로 읽을 수 있습니다. 제품별 객체 경로나 store action을 다시 번역하지
않아도 됩니다.

## 적용 전에 확인하기

편집 중에는 잘못된 주소나 스키마에 맞지 않는 값이 들어올 수 있습니다.
`validatePatch`는 현재 값을 바꾸지 않고 변경 가능 여부를 확인합니다. 확인을
통과한 작업은 `commit`으로 적용합니다. 여러 operation을 넘기면 모두
적용되거나 아무것도 적용되지 않습니다.

예상할 수 있는 실패는 `{ ok: false, code }`로 돌아옵니다. 호출자는 예외를
복구하는 대신 결과를 보고 사용자에게 다음 행동을 안내할 수 있습니다.

## 적용된 변경을 함께 사용하기

성공한 `commit`은 실제로 적용된 operation을 남깁니다. 구독자는 그 변경을
받아 다른 화면을 갱신하거나 저장을 시작할 수 있습니다. 실패한 변경이나
값이 달라지지 않은 변경은 알림을 만들지 않습니다.

이 계약에는 여섯 가지 진입점만 있습니다.

| 하고 싶은 일 | 호출 |
| --- | --- |
| 현재 값 읽기 | `document.value` |
| 한 위치 읽기 | `document.at(pointer)` |
| 여러 위치 찾기 | `document.query(jsonPath)` |
| 변경 검사하기 | `document.validatePatch(operations)` |
| 변경 적용하기 | `document.commit(operations, options?)` |
| 적용된 변경 구독하기 | `document.subscribe(listener)` |

이 작은 계약 위에 선택, 복사와 붙여넣기, 실행 취소 같은 편집 기능을 조합할
수 있습니다. React나 Zod처럼 이미 사용 중인 도구도 별도 Connector로
연결합니다. 먼저 직접 사용해 보려면 [Quickstart](quickstart.md)에서 작은
카드 문서를 만들어 볼 수 있습니다.
