# 왜 json-document인가

문서 앱에서 제목을 고치고, 표에서 셀을 고르고, 보드에서 카드를 옮기는
모습은 서로 다릅니다. 노트는 블록을 밀고, 표는 칸을 채우며, 보드는
카드를 다른 줄로 옮깁니다. 저장과 실행 취소, 다른 탭의 구독, 여러
사람이 같이 쓰는 기록은 화면마다 더 다르게 생깁니다.

그 아래에서는 같은 일이 반복됩니다. 지금 값을 읽고, 고칠 자리를
가리키고, 그 변경이 유효한지 본 다음, 적용된 결과를 다른 화면과 다른
참여자에게 같은 뜻으로 전합니다.

제품마다 이 층을 다시 만들면 주소와 변경 형식이 화면과 함께 갈라집니다.
노트의 블록 식별자, 표의 행·열 인덱스, 칸반의 카드 이동 사건이 각자
실행 취소와 협업 로그의 원천이 됩니다. 화면을 하나 더 붙일 때마다 같은
기반을 다시 짭니다. 같은 JSON을 쓰는 제품인데도 문서 화면과 표 화면이
서로의 변경을 번역해야 합니다.

json-document는 그 공통 층을 화면과 분리된 문서 커널로 둡니다. 주소와
변경과 구독의 계약을 공유하면, 선택과 복사, 장르의 손, 브라우저
플랫폼, 이미 쓰는 라이브러리를 그 위에 필요한 만큼 붙일 수 있습니다.
화면은 제품이 그립니다.

## 값을 다루는 하나의 계약

표의 셀과 문서의 블록은 생김새가 달라도 JSON 안에서는 주소를 가집니다.
한 위치는 JSON Pointer로 가리키고, 여러 위치는 JSONPath로 찾습니다.
값을 바꿀 때는 JSON Patch를 씁니다.

변경 형식 자체는 상태가 없습니다. 같은 patch를 저장소가 읽고, 다른
탭이 읽고, 나중에 만든 화면도 같은 뜻으로 읽습니다.

지금 값과 그 값에 대한 알림을 붙인 상태가 `JSONDocument`입니다. 잘못된
주소나 스키마에 맞지 않는 값은 현재 문서를 건드리지 않고 걸러집니다.
통과한 변경만 원자적으로 적용되고, 실제로 값이 달라진 변경만
구독자에게 전달됩니다. 현재 값을 읽고, 한 위치와 여러 위치를 찾고,
검사하고, 적용하고, 구독하는 일이 이 계약의 전부입니다. 호출 모양은
[API](api.md)에 있습니다.

## 같은 문을 여는 협업

혼자 쓰는 문서와 여러 사람이 쓰는 문서는 구현이 다릅니다. 로컬 문서는
지금 값에 patch를 바로 적용합니다. 협업 엔진은 참여자가 쓴 변경을 인과
순서로 모아 같은 값에 수렴시킵니다.

편집기가 받는 문은 같습니다. 현재 값을 읽고, 주소를 찾고, patch를
검사하고, 적용하고, 구독합니다. 로컬에서 그리던 화면은 같은 문서 API로
협업 구현을 받습니다. 엔진이 계산하는 것은 변경의 인과와 현재 값입니다.

협업은 값을 다루는 같은 계약을 인과 변경으로 구현합니다. 한 사람의
값과 손가락을 되돌리는 로컬 History와, 다른 참여자를 덮어쓰지 않고 내
기여만 끄고 켜는 협업 History는 여기서 갈라집니다. 자세한 계약은
[Collaboration](collaboration.md)에 있습니다.

## 편집하는 동안만 필요한 상태

문서의 값만으로는 사용자가 어느 블록을 보고 있는지 알 수 없습니다.
블록을 클릭했다고 JSON을 바꿀 이유도 없습니다. 고른 대상, 화면에 보이는
순서, 복사한 내용, 되돌릴 기록은 편집하는 동안만 필요합니다.

Editing은 이 상태를 JSON Document 옆에 둡니다. 화면은 클릭과 키 입력을
사용자의 요청인 Intent로 바꾸고, editor는 현재 문서와 편집 상태를 읽어
처리합니다. Selection은 대상을 기억합니다. Topology는 정렬과 필터를 거친
보이는 순서를 알려 줍니다. Clipboard는 JSON과 사람이 읽을 텍스트를 함께
나릅니다. History는 값과 선택을 같이 되돌립니다.

같은 문서 위에 선택과 작업을 더하는 일이 Editing입니다. 따라 가려면
[Intent guide](intent-guide.md)에서 시작합니다.

## 장르의 손

문서 한 줄, 키로 집는 객체, 격자, 나무, 칸반, 데이터베이스는 서로 다른
제품처럼 보입니다. 그 아래에서는 같은 문서와 같은 편집 상태를 씁니다.
다른 것은 그 장르가 손을 얹는 방식입니다.

Hands는 그 전형적 손의 최소 완성본입니다. 한 줄 목록을 집어 옮기는 손,
칸을 채우는 손, 가지를 접는 손이 선반에 있습니다. Document, Order,
Object, Sheet, Tree, Kanban, Database가 그 목록입니다. 고르려면
[Hands](hands.md)로 갑니다.

## 플랫폼, 라이브러리, 제품 화면

브라우저에서 쓰려면 키보드와 clipboard, contenteditable 같은 플랫폼
계약을 같은 공개 API에 맞춰 번역해야 합니다. Adapter가 그 일을 합니다.
키 chord는 의미 command가 되고, 브라우저 clipboard 사건은 copy, cut,
paste에 붙습니다.

React로 그리거나 Zod로 검사하려면 이름 있는 라이브러리의 입출력을 같은
계약에 맞춰야 합니다. Connector가 그 일을 합니다. document 변경은
React 구독으로 흐르고, 표의 보이는 행과 열은 Sheet의 Topology가 됩니다.

툴바, 리스트박스, 격자, 문서 줄, 캔버스, 나무, 보드는 제품이 그리는
화면입니다. 편집 상태를 읽어 되돌리기 버튼을 끄거나, 고른 칸을 칠합니다.

플랫폼 계약과 라이브러리 연결과 호스트 화면은 높이가 같고 하는 일만
다릅니다. 필요한 것만 고릅니다. [Adapters](adapters.md)와
[Connectors](connectors.md)에서 이어서 읽습니다.

## 편집 플랫폼의 커널

json-document는 여러 화면이 같은 문서를 쓰게 하는 편집 플랫폼의
커널입니다. JSON Document와 Collaboration이 값을 다룹니다. Editing이
손과 기억을 더합니다. Hands가 장르의 전형을 보여 줍니다. Adapter와
Connector와 제품 화면이 그 손을 실제 환경에 붙입니다.

여러 화면이 같은 주소와 실행 취소와 협업을 쓰게 하려는 자리가 이
커널입니다. 먼저 값을 만져 보려면 [Quickstart](quickstart.md)에서 작은
카드 문서를 만듭니다. 층이 어떻게 이어지는지는 [Concepts](concepts.md)가
지도입니다.
